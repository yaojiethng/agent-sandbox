## Upcoming Milestones

### M3 - Autonomous Task Execution, Manual Review Workflow

**Objective:** Move from interactive prompting to structured single-task execution with enough logging to verify the agent is doing useful work. Requires the two-layer foundation from M2.

**Depends on:** M2 two-layer architecture (headless mode requires the capability layer tool interface; task briefs are the operator input channel from M1.5).

**Finding -- Sub-milestone containment (recorded, not designed):** Milestones and sub-milestones are intended to be self-contained, but partial implementations from later milestones are frequently needed while the current milestone is incomplete. This suggests that how features are cut into sub-milestones, and how strictly they are sequenced, may be the wrong seam. The sub-milestone-as-container model is recognized as a candidate for re-examination, not as settled. Design and any restructuring is deferred to M3. The current deferred-items / sub-milestone task-list system is maintained until then.

#### T9 - Session, harness and image identity

The identity here is a label set, not an object: a value stamped on an artifact at creation, mutated by a transition, and read back at a boundary. T9 owns the invariant across the carriers - every label names its owner, every carrier agrees, every boundary validates what it reads - and the track holds one record per surface rather than one record for the track. Its rows group by stage: stamp, carry, read, validate.

- [ ] **Separate harness identity from the mounted-project session state** -- the sandbox hosts any mounted project, not only agent-sandbox (the harness dogfoods its own development as one such project). `session_state` (`sandbox/.git/SESSION_STATE`) tracks the mounted project's progress but also carries harness-identity fields: `init_sha` and `host_head_sha` name the branch point without stating which repository they belong to (harness vs mounted project), and `interface_contract_version` is a harness wiring contract, not project state. The agent has no explicit harness version to read; image digests and the worktree HEAD are host-side identities by design (ADR `harness_versioning.md`). Design a `HARNESS_STATE` (e.g. `HARNESS_VERSION`, `interface_contract_version`) distinct from the project `session_state`, decide whether the harness fields subsume or combine with the contract check (ADR `interface_contract_compatibility.md`), disambiguate `init_sha` / `host_head_sha` so each names its owner, and version the session-record pair (`.compose/<id>.yml` + `.git/SESSION_STATE`) as part of the design: the pair is the resume contract, written by host and read by container, and today only the container boundary carries `interface_contract_version`, so a format change to either half breaks resume at runtime undetected. Grounded by the uncomplect review: [`devlog/discussions/20260923-design-active-session_identity_and_sandbox_command_ergonomics.md`](../devlog/discussions/20260923-design-active-session_identity_and_sandbox_command_ergonomics.md).
