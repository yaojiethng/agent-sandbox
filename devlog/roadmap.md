## Upcoming Milestones

### M3 - Autonomous Task Execution, Manual Review Workflow

**Objective:** Move from interactive prompting to structured single-task execution with enough logging to verify the agent is doing useful work. Requires the two-layer foundation from M2.

**Depends on:** M2 two-layer architecture (headless mode requires the capability layer tool interface; task briefs are the operator input channel from M1.5).

**Finding -- Sub-milestone containment (recorded, not designed):** Milestones and sub-milestones are intended to be self-contained, but partial implementations from later milestones are frequently needed while the current milestone is incomplete. This suggests that how features are cut into sub-milestones, and how strictly they are sequenced, may be the wrong seam. The sub-milestone-as-container model is recognized as a candidate for re-examination, not as settled. Design and any restructuring is deferred to M3. The current deferred-items / sub-milestone task-list system is maintained until then.

#### M3.1 - Backpressure

The copy-delivery Markdown `pre-commit` hook is the first instance ([`git_hooks.md`](../docs/adr/git_hooks.md)); mount delivery carries no hook under the current delivery constraint. The test-family split landed in handover `20260920-03`. This sub-milestone owns the backpressure mechanisms: the commit-time hooks and the lint rules that give code and prose commit-time feedback, and the cost of running those gates.

- [x] **Mount-delivery hooks (constraint change)** -- git hooks for mount delivery require changing the delivery model's host-exposure constraint (an agent-writable hook in the mount `.git` executes on the host). The constraint change and its security cost are the deliverable; implementation follows only if the constraint changes. **Resolved without the constraint change** (iteration `20260921-11`): the host-initiated install model gives the host checkout the commit gate the mount model could not. The operator runs `scripts/manual/install_host_git_hooks.sh` on the host checkout; the container never writes the host `.git`, so the rejected host-exposure posture is preserved. Recorded in [`docs/adr/git_hooks.md`](../docs/adr/git_hooks.md) entry 2026-09-21.
- [x] **ShellCheck as a git hook** -- extend the commit hook to run the ShellCheck gate over staged shell files, giving shell rules the same commit-time backpressure as the Markdown rules. Iteration `20260921-07`: `pre-commit.sh` now gates staged shell files at `-S warning` alongside staged Markdown, sharing the `--no-verify` bypass and the tool-absent note-and-allow behavior; recorded in `docs/adr/git_hooks.md` entry 2026-09-21.
- [x] **Doc-format lint rules** -- add lint coverage for the documentation-format discipline: a rule detecting manually column-wrapped prose (hard-wrapped instruction blocks; the `MD013` line-length rule is disabled per the no-wrap policy, so the wrap has no detector). Resolves the hard-wrapped-instruction-blocks and editing-a-doc-whose-own-policy-forbids families; the plain-ASCII `doc-ascii` rule already covers non-ASCII. **Landed** across iterations `20260921-10` (introduced `scripts/lint/doc-wrap.mjs` in the workflow, not live) and `20260921-11` (enabled after a tree-wide zero-findings confirmation; removed the obsolete manual unwrap tool `scripts/manual/unwrap_prose.sh`). The one-paragraph-per-physical-line rule is live for all Markdown files, including the staged-file hook; the config-driven `legacyFiles` seam remains available for any carve-out.
- [x] **Sourced-lib / library lint rules** -- a lint check that sourced-library functions (`src/libs/`, `src/build/`) use `return`, not `exit`, and that sourced-lib reads do not redirect from unguaranteed paths (the conventions-doc rules from the M3 feedback close). Resolves the [O] library `return`-not-`exit` family. Iteration `20260921-08`: `scripts/check_lib_contract.sh` enforces convention 3.1 (exit in a function body) and 4.4 (guarded while-read redirects), wired into `scripts/lint.sh`; the two current-tree violations (`parse_help_flag`, `env_load`) were fixed to open at zero findings.
- [x] **Lint gate duration** -- make the full `scripts/lint.sh` run cheap enough for every commit. The copy-delivery hook gates the staged Markdown and shell lists; the full run previously cost ~30s because the shell gate linted every tracked file in one batch (recorded in handover `20260921-01`), and that single-invocation batch treated the first file as "the script" and suppressed script-context warnings on the rest (the study's measured 134-of-135 mask). **Landed** in iteration `20260921-12`: `check_shell.sh` runs shellcheck once per file, in parallel, cutting the shell gate from ~30s to ~1.5s, and `lint.sh` runs the shell, lib-contract, and markdown gates concurrently. Per-file strict checking is also more thorough than the batch: it exposed 8 leaked sites the lenient batch masked, each patched rather than re-suppressed. Measurement and recommendation: [`devlog/discussions/20260921-study-active-lint_and_tests_duration.md`](../devlog/discussions/20260921-study-active-lint_and_tests_duration.md).
- [x] **Test suite duration** -- reduce the total test-suite time. The suite reported ~37s wall and was described as wait-dominated at iteration `20260921-09`; a fresh 2026-09-21 measurement (supplement to the lint-duration study) records user ~32s / sys ~14s over ~40s wall and shows the cost is per-file process and child-CPU latency, not busy-waiting. Parallel `xargs -P8` measured ~7.8s with all 58 files green. **Operator decisions (2026-09-21):** yes to running the files in parallel; yes to a per-test deadline with default ~5s; the runner adoption is subject to an upcoming two-branch comparison. Approaches: a keep-current branch (dependency-free `xargs -P8` parallel + a pure-bash deadline) vs a bats-core branch; the authoritative merge decision follows comparing the two. The study also flagged a bad testing direction in `test_doc_wrap_rule.sh` (linting the whole project tree), amended with the Doc-scope fix and the audit (see [`docs/development/testing-conventions.md`](../docs/development/testing-conventions.md) Anti-Pattern 8). Lint and test duration are owned separately. **Resolved (2026-09-22):** branch A (keep-current) merged - `xargs -P8` parallel dispatch and a pure-bash per-file deadline land on `scripts/run_tests.sh`; 712 units, 46s serial to 9.7s parallel (~4.8x), order gate 58/58, lint Clean. Bats-core rejected; the decision is in [`devlog/discussions/20260922-design-settled-m3_1_test_harness_decision.md`](../devlog/discussions/20260922-design-settled-m3_1_test_harness_decision.md) and ADR [`docs/adr/test_harness.md`](../docs/adr/test_harness.md).
- [x] **Individual per-test timeout** -- a per-test-file deadline so a hanging test cannot hang the whole suite and the tool. **Subsumed into M3.1** (2026-09-21). Operator decision: yes; default ~5s (the observed max of the corrected suite); the exact mechanism (the runner's pure-bash deadline, or bats' native `BATS_TEST_TIMEOUT`) is subject to the two-branch comparison. Implementation rides the same branches as Test-suite duration. **Resolved (2026-09-22):** the pure-bash per-file deadline (default `TEST_TIMEOUT=5`, kill-on-expiry reported `TIMEOUT` and counted a failure) lands on `scripts/run_tests.sh`; bats' native `BATS_TEST_TIMEOUT` rejected with the migration (see the harness-decision record).
- [x] **Test-harness improvement (unified plan)** -- a single task consolidating the M3.1 harness work, owned on the main line. **Landed** across iterations `20260922-02` through `20260922-08` (U1-U7): per-test subshell isolation with fail-fast, per-test-unit accounting, the untyped allocator, the `assert_run` capture-and-assert helper, stray-`mktemp` routing, the benign-non-zero convention, the assert-the-meaning label audit (zero violations), the reversed-run order gate (`scripts/check_test_order.sh`, 58/58 clean), and the final fresh-subagent per-assertion sweep (which also restored `scripts/prune.sh`'s exec bit). Suite at 710 units, lint Clean. Per-test isolation is pulled forward (subshell-per-test + fail-fast + unit accounting); the authoring checklist (capture-and-assert; assert-the-meaning-not-the-string; per-test fixture directories; unified explicit teardown; no benign-non-zero intermediates; disambiguating labels; order-independence) is applied as model-and-measured-violations with a final full per-assertion fresh-subagent sweep; the untyped per-test allocator (`get_fixture_dir` / `get_test_dir`, no reuse between tests, `FIXTURE_DIR` compatibility) provides unified teardown. Plan: [`devlog/discussions/20260922-design-active-test_harness_improvements.md`](../devlog/discussions/20260922-design-active-test_harness_improvements.md). Supersedes the two-branch parity framing and its status-per-branch recording. **Decision (2026-09-22):** branch A (keep-current) merged; bats-core rejected; branch B archived. The re-port re-measured both on equal footing (identical 696-unit name sets); verdict and measured values: [`devlog/discussions/20260922-design-settled-m3_1_test_harness_decision.md`](../devlog/discussions/20260922-design-settled-m3_1_test_harness_decision.md); ADR [`docs/adr/test_harness.md`](../docs/adr/test_harness.md).

The rows below are the noncritical, harness-independent leftovers from the harness comparison. They sit under backpressure because a test harness that fails with a sharp reason returns better feedback to the agent while implementing.

- [x] **Replace the RETURN-trap cleanup in `compose_generate`** -- `src/build/compose.sh` cleans its staging dir with `trap 'rm -rf "$staging_dir"' RETURN`; under bats' functrace the trap fired across subprocess boundaries and deleted staged files early (branch-B finding). The keep-current runner never enables functrace, so the pattern is latent, not broken: restructure to an explicit cleanup so temp removal does not depend on shell-functrace semantics. **Landed (2026-09-22):** `compose_generate` now cleans its staging dir explicitly on every return path (the `input file not found` early return and normal completion) and returns the merge rc unchanged; the RETURN trap is gone.
- [x] **Harden the entrypoint-signal tests with `exec` and a settle grace** -- `test_git_hook.sh` and `test_capability_entrypoint_mount.sh` background a copy of the entrypoint and send it SIGTERM; the signal can arrive before the TERM trap registers, so `wait` can return 143. The branch-B re-port verified the fix (`exec` inside the background subshell so the signal reaches the trap-bearing process, plus a short settle). The race is latent on the keep-current runner; adopt the verified fix. **Landed (2026-09-22):** both invoke helpers now `exec` the entrypoint (so `$pid` is the trap-bearing process; the readiness marker prints at `entrypoint.sh:230/177` before the `trap 'exit 0' TERM` at line 319) and settle `0.2s` before the SIGTERM; `EP_RC==0` is preserved on the clean signal path.
- [x] **Report a reason on rc-driven test-file failures** -- the runner prints `FAIL <file>` when a file's subshell exits non-zero without a `fail()` marker (a crash or a trailing non-zero command); the `grep "^  FAIL:"` reason list is then empty, so the failure carries no accompanying reason in the summary. The suite-side guards (no-assertion, fail-fast) cover the passing side; this is the reporting side. Raised from the harness evaluation. **Landed (2026-09-22):** the runner now appends `file exited <rc> with no FAIL: marker (crash or uncaught non-zero command)` under `FAIL <file>` when a file fails without a `FAIL:` marker; extended the selftest crash case to pin it; marker-driven output and the 712-unit count are unchanged.
- [ ] **Test-suite read-through and mechanism documentation (operator onboarding)** -- a fully agent-guided close read of the test harness and every test, so the operator ends with a working impression of what each test is and does, and picks up the BDD/TDD discipline. Four phases, in dependency order: (1) the harness mechanism -- `scripts/run_tests.sh`, the selftest, and the `tests/libs/test_common.sh` assert/alloc vocabulary -- documented so the unit-test-run mechanism is described and understood (deliverable: a `docs/development/` mechanism write-up); (2) the small `src/libs/*` units, one test file per session, ordered by leaf-first readability; (3) the `src/build/` and `src/capability/` components with their trace tests; (4) the `make`-workflow drivers and their test families, least digestible last. Within phases 2-4, every test is read against a fixed inventory frame -- what property is asserted, why it matters, how it is set up and triggered, and how confident we are the assertion bites (mutation/negative-test check) -- captured incrementally in a read-through discussion record. Each test is named in BDD terms (Given/When/Then) to drive the TDD learning outcome. Not a code change; the read-through is after-the-fact understanding and may surface noncritical robustness notes already tracked as M3.1 rows.
