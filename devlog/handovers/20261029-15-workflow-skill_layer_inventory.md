# Handover - Inventory the skill layers and hold their access

## Objective

Replace the three-layer skill model with the four layers the runtime actually loads, generate the inventory from pi's loader, and make a collision and a shipped-layer link outside its root hard findings.

## Scope

Delivers the M3.3.3 subtask **The skill layer is inventoried, and its access is held**, pulled from M3.3.6. The four layers, highest precedence first, are project, provider, agent-sandbox and workflow. The map is generated by `scripts/skill_map.mjs` with pi's `loadSkills`, and `scripts/check_skill_map.sh` runs it as a lint gate. The map is printed, not committed.

The access rule is one-way. A shipped layer -- provider, agent-sandbox or workflow -- may link only within its own source root. A project-layer skill may link anywhere in the project tree, including into a shipped layer. A name collision, a discovered `SKILL.md` that pi does not load, and a broken relative link are hard findings. A name/directory mismatch and a missing agent-sandbox maintenance record are warnings.

The docs and the ADR state the four layers and the precedence; the previous three-layer descriptions are corrected. `writing-for-agents` loses its eleven provider-layer links; the principles are named in code spans instead, and the provenance record is the next subtask. The map warns about the four agent-sandbox skills without a record; that is the next subtask's work.

Out of scope, one sentence each with the reason: the provenance records and the tree-wide record gate stay with **The provenance records and the tree-wide gate**, because the map only warns; the full discoverability map, the context budget and the hops stay in M3.3.6, because the layer inventory does not need them; and the project skills surface gains no `cells` row, because pi auto-discovers it and the full map owns the interface declaration.

## Decisions

| Decision | Rationale | Where recorded |
|---|---|---|
| The four layers are project, provider, agent-sandbox and workflow, highest precedence first | The docs merged the two package roots and omitted the project layer; the runtime holds four roots with different owners and different package entries. | this record; the ADR; the four docs |

| A shipped skill may link only inside its layer root; a project skill may link into a shipped layer | A shipped skill is read from `/opt` or the provider home, where the project tree is absent; the project tree is where the project layer is read. | this record; the ADR; `scripts/skill_map.mjs` |
