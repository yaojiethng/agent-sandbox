# Make the name and the description a signpost

A skill reaches a reader through its name and its description. The body loads only after the reader decides to open it.

**The name.** The name is the shortest true summary of the description. It states the judgement or the defect the skill prevents, in the word the domain already holds, and stays at five words or fewer.

Name the act, not the quality. `proximity` names a quality; `keep a subject near` names the act.

Three readers meet the name: the agent, which sees it advertised beside the description; the operator, who recalls it when the work calls for it; and another document, which cites it. The last makes the name the skill's public handle.

Do not name how the skill is built. A build phrase spends the name on words nobody searches for.

A name another skill already holds does not load, because the first skill discovered keeps it. A name that understates the skill is not recalled; one that overstates it is recalled for the wrong situation.

A rename reaches every document that cites the name, so a rename carries a list of files to change.

**The description.** Spend the description on words an agent can match: the work the skill does, named by its object, and the situations that call for it. Two phrases for one situation spend the space twice.

A skill only the operator invokes is read from the operator's list, so its description uses the words that operator searches with.

**The signpost.** A skill's name and description are its signpost: the only words an agent holds before it loads the body. Use `communication-principle-maximize-conceptual-leverage` at `$AGENT_HOME/agent/skills/communication-principle-maximize-conceptual-leverage/SKILL.md` to choose the leading word and record it as `metadata: leitwort:`.

Use the leading word in the name, the description and the body. It steers the agent toward the domain of the problem. Derive the signpost from the leading word, and prefer search terms that describe a situation where the skill is useful.

**What this pattern does not cover.** The choice of leading word. What the skill does once it is loaded, and how its body is written.

**The test.** Read the name and the description. Do they summarize the skill's purpose? Would an invoker recall the skill in a situation that needs it? Cut anything that would not match an invocation query.
