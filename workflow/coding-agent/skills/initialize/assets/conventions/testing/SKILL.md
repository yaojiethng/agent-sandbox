# testing

**This skill is a stub.** The workflow expects a `testing` convention at this point, and what it found here is an uninitialized placeholder.

A testing convention states how this project verifies a change: the command, where it runs, what it covers, and whether network access is permitted. Until the project states it, the workflow cannot verify the work it produces.

These questions may help establish it. Take them or leave them:

- What command verifies a change, and what does it run?
- Does it run on the operator's side, in the container, or in both?
- Are network calls permitted during a test, and if so against what?
- What must a test cover - unit, integration, or the operator's manual check?
