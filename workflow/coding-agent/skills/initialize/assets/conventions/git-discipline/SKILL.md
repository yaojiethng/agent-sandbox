# git-discipline

**This skill is a stub.** The workflow expects a `git-discipline` convention at this point, and what it found here is an uninitialized placeholder.

A git-discipline convention states the vocabulary this project accepts in its history: the commit types, the subject and body rules, the branch scheme, and how a correction is made. Until the project states it, the workflow has no vocabulary for the commits it lands.

These questions may help establish it. Take them or leave them:

- Which commit types does this project accept, and what does each mean?
- What are the subject and body rules?
- What branch scheme does the project use, and where does work land?
- How is a correction to a landed commit made?
