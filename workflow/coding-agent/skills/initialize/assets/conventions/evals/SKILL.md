# evals

**This skill is a stub.** The workflow expects an `evals` convention at this point only if the project runs evals, and what it found here is an uninitialized placeholder.

An evals convention states how this project scores an instruction set's behaviour: where a case set lives, what a case carries, and which model plays which role. This convention is optional; a project without it is not degraded.

These questions may help establish it. Take them or leave them:

- Does this project run behaviour evals at all?
- Where does a case set live, and what does a case carry?
- Which model plays the subject, and which the judge?
- What does the project do with an eval's result?
