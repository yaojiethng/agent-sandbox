# docs

**This skill is a stub.** The workflow expects a `docs` convention at this point, and what it found here is an uninitialized placeholder.

A `docs` convention states where this project keeps its durable documents, how that tree is organized, and which documents a reader must find. It is the document reference: the tree and its structure, not the writing style, which is the `communication` standard. Until the project states it, the workflow has no document tree to maintain or cite.

These questions may help establish it. Take them or leave them:

- Where does the document reference live, and what does the folder structure mean?
- Which documents ship with the product and which stay with the repository?
- Who reads each document, and what must a document declare for them?
- Which document kinds exist, and what does each kind carry?
