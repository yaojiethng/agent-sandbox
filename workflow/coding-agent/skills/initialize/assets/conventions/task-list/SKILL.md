# task-list

**This skill is a stub.** The workflow expects a `task-list` convention at this point, and what it found here is an uninitialized placeholder.

A task-list convention states how this project records its work: where the list lives, how an item is identified and filed, what a milestone is, and whether a separate backlog and changelog exist. Until the project states it, the workflow has no task list to read.

These questions may help establish it. Take them or leave them:

- Where does the task list live, and is it one file or several?
- How is an item identified, and how is its status changed?
- What defines a milestone's goal and its definition of done?
- Is there a separate backlog for work not yet scheduled?
- Is there a changelog, and what belongs in it?
