# Write for a small working memory

**Working memory is small.** Anything not on screen is forgotten. Put what the reader needs beside the part that needs it.

- When you write a caveat, put it beside the rule it qualifies.
- When you refer to the reader's place in a procedure, restate it.
- When parts have an order the reader needs, use it: definition, rule, caveat.
- When the caveat is in a second document, put it beside the rule it qualifies.

**Why.** When a part sits away from what it needs, the text carries extraneous load: the reader spends working memory on the text rather than the meaning, holding the rule while reading its caveat or reanalysing the rule once the caveat arrives. Put the part beside what it needs, and the memory goes to the meaning: the reader parses each part once.

**Where another rule wins.** This rule governs where a part sits relative to what it needs, across the text; the sentence's structure is another rule's.

- **Clause order and reanalysis:** `order-for-incremental-parsing` attaches each phrase to the structure already built, within one sentence, including the pinning of "only" and "not".
- **Undefined terms:** `define-terminology-before-use` introduces a term's meaning before its first use.
- **A second subject in a section:** `single-train-of-thought` keeps one line of reasoning.
- **Unreachable or external references:** `link-what-the-reader-can-open` for a target the reader cannot open; `write-for-the-reader` for context outside the text.
- **A second copy:** `single-source-of-truth` keeps one authoritative statement.
- **A wind-up before the point:** `cut-metadiscourse` cuts the prose about the text.

**The test.** At each part, ask what the reader must still hold. If the answer is earlier text, the part is apart from what it needs.
