# Minimal corrections

A correction restores the intended artifact and adds nothing beside it.

**The pattern.** Count the artifacts the correction produces. One is the answer.

| The correction | The artifact it adds | What one artifact looks like |
|---|---|---|
| a repair commit | a second commit recording that the first was wrong | the corrected commit |
| a `[CORRECTION]` paragraph in a record | a narrative of the deviation | the corrected claim |
| a rule preventing the defect | a surface standing beside the rule | the rule, stated once, where it already lives |
| a gate proving the rule | a measuring device | the rule, in the procedure that enforces it |
| a handover entry per correction | a record per correction | the unit's own record |
| an amendment that also tidies | a change the defect did not require | the corrected lines alone |

A correction that also improves something adjacent is two changes. Land the improvement as its own.

**Why.** Each artifact added is itself reviewable, itself maintainable, and itself capable of being wrong. A correction that adds a layer moves the defect rather than removing it, so the cost of a mistake multiplies by the number of layers the correction builds.

**The test.** How many artifacts does this correction produce? One is the answer. Then, does the diff touch only the lines that were wrong?
